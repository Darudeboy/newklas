# Требования к задачам Story

Актуально на 23 октября 2026 года. Источник — текущая реализация `scripts/release_checker.py`.

Правила применяются к Story, включённым в состав релиза через связи `consist of` / `is part of`. Проверки выполняются независимо: отсутствие PR не отменяет проверку комментария, списанного времени и остальных требований.

## Основные требования

| № | Что проверяется | Требование |
|---|---|---|
| 1 | Описание | Должно быть заполнено. |
| 2 | Контур | Хотя бы один лейбл: `web`, `back` или `mobile`. Регистр не важен. |
| 3 | Новая функциональность | Поле `customfield_24000` заполнено значением **«Да» или «Нет»**. |
| 4 | Требуется НТ | Поле `customfield_18400` заполнено значением **«Да» или «Нет»**. |
| 5 | Epic Link | Обязательно заполнен (`customfield_10006`). |
| 6 | КЭ | Поле заполнено; каждая КЭ Story присутствует среди КЭ релиза. Для мобильных релизов проверка отключена. |
| 7 | Бизнес-требования | В блоке требований — **«Зафиксировано»**, обязательно со ссылкой. |
| 8 | Функциональное решение | В блоке требований — **«Зафиксировано»**, обязательно со ссылкой. |
| 9 | Архитектура | **«Не меняется»** → поле «Архитектурные изменения» содержит только «Не влияет на архитектуру». **«Утверждена»** → есть ссылка и выбрано хотя бы одно допустимое архитектурное изменение, без «Не влияет на архитектуру». |
| 10 | Срок заполнения требований | Блок требований (`customfield_21100`) и архитектурные изменения (`customfield_23700`) не должны меняться после первого перехода в **Ready for UAT, UAT или Done**. Код проверяет именно изменения полей после перехода. |
| 11 | Сабтаска «Анализ архитектуры» | Должна существовать и быть закрыта разрешённым сотрудником. Проверяется **автор последнего перехода в закрытый статус**, а не текущий исполнитель. |
| 12 | Комментарий тестировщика | Нужен комментарий от тестировщика из разрешённого списка. |
| 13 | Списание времени | У каждого тестировщика, оставившего комментарий, должно быть списанное время — в Story или связанной тестовой Task. Для Метляева Игоря Андреевича и Никонова Александра Алексеевича предусмотрено исключение, **которое не действует в HRC**. |
| 14 | Тестовое покрытие | Должны быть **прямо связанные тест-кейсы из HRPQA**. |
| 15 | Статусы тест-кейсов | Все проверяемые ТК должны иметь статус **Approved**. |
| 16 | Вид тестирования ТК | «Новая функциональность» = **Да** → **«Новый функционал»**; **Нет** → **«Регресс»**. |
| 17 | PR | PR должен быть связан **с самой Story**. PR только на дочерней Task не заменяет эту связь. Сейчас отсутствие PR оформляется предупреждением, а этап является необязательным. |
| 18 | GigaCode / AIFIXED | При обнаружении использования GigaCode в PR/коммитах Story или связанных Task требуется `AIFIXED`. Скрипт добавляет его автоматически; ошибка добавления фиксируется как ошибка. В режиме dry-run запись отключена. |

Если блок требований/архитектуры некорректен, а Story уже в Ready for UAT, UAT или Done, дополнительно фиксируется ошибка о влиянии на метрику модели зрелости.

## Дополнительные условия

### Cloud-релиз

Если в названии релиза есть `Cloud`, у Story обязателен лейбл `Пульс_внешний_рынок`.

### Проект SBRPPL

Обязательны:

- Лейбл `#Пульс_3лица`; допускается вариант без `#`.
- Заполненные **Story Points** (`customfield_10002`). Проверяется заполненность, а не положительное значение.

### Task в составе Story

Связанные через `consist of` / `is part of` задачи типа Task должны быть закрыты, решены или отменены.

Допустимые статусы: `Closed`, `Закрыта`, `Закрыто`, `Resolved`, `Решена`, `Решено`, `Cancelled`, `Отменён`, `Отменен` — без учёта регистра.

Если Task находится в том же проекте, что и Story, у неё также обязателен Epic Link. Совпадение Epic со Story отдельно не проверяется.

### Соответствие названия описанию

Дополнительная необязательная проверка через GigaChat.

### Исключения для мобильных релизов при проверке КЭ

## Время тестирования

Превышение времени — **неблокирующее отклонение**.

Суммируется время в статусах `Ready for IFT`, `IFT`, `Ready for UAT`, `UAT`. Допустимый предел — **115% норматива**. Время считается в днях по длительности пребывания в статусах, а не по списанным трудозатратам.

| Проект | Норматив, дней | Предел, дней |
|---|---:|---:|
| HRM | 6 | 6,9 |
| HRC | 6 | 6,9 |
| SFILE | 6 | 6,9 |
| NEUROUI | 5,5 | 6,325 |
| HRPPA | 3,6 | 4,14 |
| PERFREVIEW | 5,2 | 5,98 |
| HRPASSIST | 10 | 11,5 |

Для остальных проектов этот норматив не проверяется.

## Отлинкованные Story

Должна существовать связь хотя бы с одним другим релизом в статусе **«Установлен на ПРОМ»**.

- Текущий релиз не учитывается.
- Отсутствие такой связи или невозможность подтвердить статус — **блокирующая проблема**.
- Подтверждённый установленный релиз разрешает наличие merged PR.
- Исключения для проверки PR (`review_confirmed`, связь с задачей/багом текущего релиза) не отменяют проверку другого релиза.
- Статусы других релизов загружаются пакетно. Кандидаты определяются по проекту текущего релиза либо по типу Release / Релиз / Релизный объект; учитываются оба направления связи.
- Неполученные задачи и неполная история связей также блокируют готовность.
